> This file is a release-note draft. `QingZoneX/qtable-web` is now public and developed in the open, but `v0.1.2-alpha` must not be represented as a published release until the exact-revision CI, full-stack E2E and tag/release gates complete.

This candidate aligns the web frontend with the QTable `v0.1.2-alpha` open-source baseline maintained across `QingZoneX/qtable-server` and `QingZoneX/qtable-web`.

## Verification gate

Remove `DRAFT / NOT YET RELEASED` only when:

- Frontend CI passes every required frontend contract check on the exact reviewed `qtable-web` main SHA;
- TypeScript and the production build pass;
- secret-history scanning passes;
- open-source readiness, dependency and license contracts pass;
- Docker image/runtime smoke and container security checks pass;
- full-stack release E2E executes against the exact `qtable-server` + `qtable-web` revisions and retains revision/screenshot/trace evidence;
- the corresponding server release gates pass; and
- the verified `v0.1.2-alpha` tag/release is created from the approved revision set.

Repository visibility is no longer a future gate: the source repositories are already public. Public visibility alone does not make an arbitrary commit or container image an official release artifact.

A workflow that never performs a real test execution cannot satisfy this verification gate.

For the complete product release notes, see the `QingZoneX/qtable-server` repository.
